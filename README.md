# lecture-exam-prep

Подготовка к кандидатскому экзамену по записям лекций: пайплайн транскрибирует видео,
индексирует тексты и генерирует ответы на билеты **строго по материалам лекций** — с цитатами
и ссылками на точный момент видео. Локальный сайт показывает готовые ответы.

Текущий курс: «История и философия науки» К. А. Скворчевского (МФТИ), 21 лекция, ~30 часов.

## Как это устроено

Система отвечает на экзаменационные билеты, имея право опираться **только** на расшифровки
лекций конкретного курса. Это не стилистическое пожелание, а определяющее ограничение: на
кандидатском экзамене спрашивают то, что читал лектор, и ответ из учебника может противоречить
его трактовке. Отсюда всё остальное — каждое утверждение несёт ссылку на фрагмент расшифровки,
у ответа есть поле `coverage` (`full`, `partial`, `not_found`), а знания вне лекций живут в
отдельном поле `outside_lectures_md`, которое интерфейс помечает явно. Присоединяясь к проекту,
помните: текст в `answer_md` без подтверждённого `chunk_id` — дефект, а не свобода изложения.

Артефакты всех этапов лежат файлами в репозитории, а не в базе данных: `course.json`,
`transcripts/<video_id>.json`, `chunks.jsonl` в формате [JSON Lines](https://jsonlines.org/),
`extracts/`, `answers/`. Так устроено потому, что пайплайн работает на двух машинах, а сайт
статический: данные переносятся между ноутбуком и кластером через git, а браузер читает их
напрямую. Формат задан [pydantic](https://docs.pydantic.dev/)-моделями в
`pipeline/src/examprep/schemas.py` — это единственный источник истины; TypeScript-типы
генерируются из их [JSON Schema](https://json-schema.org/), поэтому `site/src/types/data.d.ts`
руками не редактируют.

Вычисления разделены между ноутбуком и GPU-кластером по внешнему ограничению, а не по
удобству: YouTube отвечает bot-check на запросы с датацентровых адресов, поэтому `ingest` и
`download` через [yt-dlp](https://github.com/yt-dlp/yt-dlp) идут с домашнего IP, а на кластер
попадает уже готовое аудио. GPU нужны ровно трём шагам — транскрибации, эмбеддингам и LLM, —
и они не должны занимать карты одновременно: порядок `transcribe` → `index` → остановка →
`vllm serve` → `answer` обязателен, `status` проверяет его соблюдение.

Повторный запуск любого шага пропускает готовое по `input_hash`, а не по факту существования
файла. Причина в цене ошибки: полный прогон ответов — это около 1900 обращений к LLM, и
терять его из-за упавшего билета нельзя, как и молча отдавать устаревший результат. В хэш
входит **текст** промпта, а не имя его файла: правка формулировки меняет ответы, и кэш,
ключованный по имени, продолжал бы отдавать старые. Добавляя новый вход в шаг, добавьте его
и в хэш.

Генерация ответа разбита на три шага вместо одного обращения к модели. Поиск возвращает 40
кандидатов на билет, из которых релевантны обычно единицы; если отдать их синтезу целиком,
модель начинает склеивать ответ из шума и достраивать недостающее по памяти. Поэтому между
поиском и синтезом стоит `extract`: дешёвый проход с `temperature=0`, который по каждому
фрагменту отвечает, относится ли он к вопросу, и возвращает тезисы с дословной цитатой.
Синтез видит только то, что этот фильтр оставил.

Поиск гибридный: плотные векторы [BAAI/bge-m3](https://huggingface.co/BAAI/bge-m3) и
[BM25](https://en.wikipedia.org/wiki/Okapi_BM25) по леммам
([pymorphy3](https://github.com/no-plagiarism/pymorphy3)), объединённые через
[reciprocal rank fusion](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf). Причина в
природе материала: это устная речь с ошибками распознавания, где вопрос сформулирован
по-учебниковому, а лектор говорит своими словами. Векторы ловят перефраз, BM25 — точное
совпадение фамилии или термина, а RRF объединяет их без калибровки шкал, которой у двух
разных метрик нет.

Цитаты проверяет код, а не модель. Каждая цитата должна найтись в том фрагменте, на который
сослались; сравнение нечёткое — по доле цитаты, покрытой совпавшими кусками, потому что модель
поправляет лектору грамматику, — но выдуманная фраза до порога не дотягивает. Непрошедшая
цитата выбрасывается, а ссылки `[n]` в тексте перенумеровываются, иначе сноска указывала бы на
чужой фрагмент. Логика в `answer/verify.py`, и ослаблять её порог, чтобы «пропускало больше»,
значит ломать главное свойство продукта.

Таймкод цитаты берётся с уровня сегмента расшифровки, а не чанка. Чанк — это окно в 90 секунд,
выбранное как единица поиска, и ссылка на его начало заставила бы человека ждать до полутора
минут до нужной фразы. Цитата ищется среди сегментов, из которых чанк собран, и ссылка ведёт на
тот, где фраза начинается; попутно точность ссылки перестаёт зависеть от размера окна.

Транскрибация работает через [transformers](https://huggingface.co/docs/transformers), а не
через [faster-whisper](https://github.com/SYSTRAN/faster-whisper), который был бы быстрее.
Причина аппаратная: [CTranslate2](https://github.com/OpenNMT/CTranslate2) собирается только под
CUDA 12, а целевой кластер — CUDA 13, и `libcublas.so.12` там нет. Побочное следствие — в
процессе не остаётся декодера сжатого аудио, поэтому шаг `prepare-audio` конвертирует записи в
16 кГц WAV заранее, и он обязателен.

Whisper запускается в последовательном длинноформатном режиме, а не в оконном с батчами.
Оконный режим быстрее, но предсказывает таймкоды независимо в каждом тридцатисекундном окне, и
при склейке они не сходятся в единую шкалу: на замерах это давало сегменты длиной до 21 минуты
и текст, «произнесённый» со скоростью 4000 символов в секунду. Для проекта, где ссылка на момент
записи и есть продукт, такие таймкоды бесполезны.

Оба тяжёлых окружения на кластере — conda для ASR и отдельное для [vLLM](https://docs.vllm.ai/)
— чужие и подключаются только на чтение; свой venv создаётся поверх них с
`--system-site-packages`. Каталоги доступны на запись, так что дисциплина держится на
договорённости, а не на правах: `scripts/setup_server_env.sh` отказывается ставить пакеты, если
не активирован наш venv. Модель MoE поднимается с `--enable-expert-parallel` не ради
производительности, а потому что иначе не собирается: размер эксперта 640 не делится на восемь
карт кратно блоку FP8-квантования в 128.

Сайт на [Vite](https://vitejs.dev/) статический и только читает `data/`; в публичную сборку на
[GitHub Pages](https://pages.github.com/) расшифровки, чанки и промежуточные извлечения не
попадают. Это не оптимизация размера: расшифровки — производное произведение от чужих лекций,
а опубликованный сайт заметно виднее файлов в репозитории. Интерфейсу они и не нужны — ответы
несут цитаты с собой и ссылаются на оригинальные видео. Список исключений задан в
`site/vite.config.ts`, и добавляя в `data/` новый тип артефакта, проверьте, должен ли он уезжать
наружу.

## Быстрый старт

```bash
cp .env.example .env          # заполнить GPU_HOST и параметры LLM

# ноутбук: метаданные и аудио
cd pipeline && uv sync
uv run examprep validate
uv run examprep ingest   --course hps-skvorchevsky
uv run examprep download --course hps-skvorchevsky
./scripts/sync_audio.sh hps-skvorchevsky

# GPU-сервер: транскрибация, индекс, ответы
cd pipeline && ./scripts/setup_server_env.sh   # venv поверх conda; не --extra gpu
uv run examprep prepare-audio --course hps-skvorchevsky   # m4a → 16 кГц WAV
uv run examprep transcribe --course hps-skvorchevsky --gpus 0,1,2,3,4,5,6,7
uv run examprep index      --course hps-skvorchevsky
./scripts/serve_llm.sh                 # в tmux
uv run examprep answer     --course hps-skvorchevsky
uv run examprep export-index

# ноутбук: сайт
cd site && pnpm install && pnpm dev
```

## Проверки

```bash
cd pipeline && uv run ruff check . && uv run mypy src && uv run pytest
cd site && pnpm lint && pnpm typecheck && pnpm test
```

TypeScript-типы генерируются из pydantic-моделей и в git не редактируются руками:

```bash
cd pipeline && uv run python scripts/export_schemas.py
cd site && pnpm typegen
```

## Что лежит в репозитории

- `pipeline/` — CLI `examprep` (Python 3.12, uv).
- `site/` — статический сайт (Vite + React + TypeScript), только чтение данных.
- `data/question-sets/` — списки экзаменационных вопросов (входные данные, правятся руками).
- `data/courses/<slug>/` — метаданные курса, транскрипты, чанки, извлечения и ответы.

Аудио, эмбеддинги и `.env` в git не попадают.

## Публикация

Сайт публикуется на GitHub Pages по адресу `https://kisnikser.github.io/lecture-exam-prep/`
воркфлоу `.github/workflows/deploy.yml` — при пуше в `main`, если менялись `site/` или `data/`.
Один раз нужно включить в репозитории: Settings → Pages → Source: GitHub Actions.

В публичную сборку **не попадают** расшифровки лекций, чанки и промежуточные извлечения: наружу
идут только ответы с цитатами и ссылками на оригинальные видео. Локально (`pnpm dev`) доступны
все данные.

## Авторские права

Репозиторий не содержит и не распространяет видео- и аудиозаписи лекций. В git попадают только
транскрипты и сгенерированные ответы; ссылки ведут на оригинальные публичные записи на YouTube.
Материалы предназначены исключительно для личной подготовки к экзамену.
